# AI Slop Cleaner

Removes the distinctive verbal tics of unedited LLM output.

## When to invoke

- Reviewing text generated by an LLM before it ships.
- Cleaning up docs, commit messages, PR descriptions, or READMEs that feel bloated.
- User says "clean this up", "remove the fluff", "tighten this", or "this reads like AI".

## Slop categories to strip

### 1. Metatalk
- "As an AI..."
- "I'd be happy to help..."
- "Certainly! Here is..."
- "I hope this helps!"
- "Let me know if you have any questions."
- "Feel free to ask..."

### 2. Empty hedges
- "It is important to note that..."
- "It's worth mentioning..."
- "Please be aware that..."
- "It should be noted..."
- "One thing to consider..."

### 3. Dictionary-expansion verbs
- "delve into" -> "explore" or just remove
- "navigate the complexities of" -> remove
- "embark on a journey" -> remove
- "in the realm of" -> "in"
- "at the end of the day" -> remove
- "pivotal" -> "key" or remove
- "leverage" (as verb) -> "use"
- "utilize" -> "use"
- "facilitate" -> "help" or "enable"
- "in conclusion" -> remove (let the conclusion speak for itself)

### 4. Fake enthusiasm
- "Absolutely!"
- "Great question!"
- "What a fantastic idea!"
- Emoji used as punctuation (unless user asked for emoji)
- Exclamation marks on declarative statements

### 5. Filler structure
- "First and foremost" -> "First"
- "Last but not least" -> "Finally" or remove
- "In today's fast-paced world..."
- "In the digital age..."
- Bullet lists where a single sentence works
- Three-point frameworks that repeat the same idea

### 6. Em-dash spam
- LLMs overuse em-dashes for emphasis. Prefer commas, periods, or parentheses. Keep em-dashes only where they genuinely mark a break in thought.

### 7. Symmetric hedging
- "while X, it is also true that Y" when the author should just pick one.
- "on the one hand... on the other hand..." with no actual conclusion.

## Rules

- Preserve the author's voice and technical content. Only strip filler.
- Do NOT introduce new claims or change meaning.
- Do NOT replace removed filler with different filler.
- Shorter is almost always better. Aim for a 20-40% reduction on unedited LLM output.
- Keep lists and structure when they aid scanning; remove when they bloat.
- Code comments: strip "This function..." if the function name already says it. Keep "why" comments, drop "what" comments.

## Workflow

1. Read the input text end-to-end once.
2. Mark every slop instance (mental pass, then a surgical edit pass).
3. Rewrite in place, preserving structure where it earns its keep.
4. Read the result aloud (mentally) -- does it still sound like the author? If it now sounds like a different AI, revert.
5. Report a word-count delta and a sample of the top 3 changes.

## Output

```
## Slop Clean Report
Before: NNN words
After:  MMM words (-XX%)

Top changes:
- "It is important to note that X" -> "X"
- "delve into the complexities" -> "explore"
- em-dash spam -> commas/periods

Cleaned text:
<result>
```
